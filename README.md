# LocalSend Chat

一个套在 LocalSend Protocol v2 之上的局域网聊天窗口。核心协议未作改动，
因此官方 LocalSend 客户端能发现它、给它发消息和文件，它也能反向发送。

当前版本：**v2.6.5**

> **非官方项目**：本项目不是 LocalSend 官方衍生版本，与上游无隶属关系。
> LocalSend 名称与图形标识归其各自所有者；LocalSend 本体采用 Apache-2.0 协议。

## 特性

- 纯局域网，无服务器、无账号、数据不上传云端
- 实现 LocalSend Protocol v2 的 `/info`、`/register`、`/prepare-upload`、`/upload`、`/cancel`
- 聊天气泡界面，8 套配色（Windows / macOS 系统典型色 + 樱雾粉）：
  深色「石墨灰 / Win11 深空 / 午夜蓝 / 经典蓝 / 荧光青」，浅色「Win11 晴空（默认）/ 纸张白 / 樱雾粉」
- 图片实时缩略图，一对多群发
- **双向拖放**：像原版 LocalSend 一样把文件拖进窗口即发送；聊天里的文件可拖到桌面/文件夹复制
- 链接分享：手机浏览器直接下载文件、复制文字
- 设备发现支持 UDP 组播 + 本机网段扫描，可手动「添加设备」
- **删除与屏蔽分离**：删除只移出列表、刷新即可重现；屏蔽才写持久化名单，且有「已屏蔽 (N)」恢复入口
- 「关于」对话框、双击版本号八次修改面板名称
- 内置「自动修复 / 修复防火墙权限」，排查连不上设备时不用手敲命令
- 单文件绿色版：内置 Python 运行时，无需安装 Python 或任何依赖

## 快速开始

1. 到 [Releases](../../releases/latest) 下载 `LocalSendChat.exe`
2. 双击运行；首次弹出 Windows 防火墙提示时勾选「专用网络」并允许
3. 手机安装官方 [LocalSend](https://localsend.org)，与电脑连到同一 Wi-Fi
4. 点「刷新设备」等待手机出现；或点「添加设备」手动填入手机 IP 与端口
5. 选中设备，输入文字后回车发送；也可以把文件直接拖进窗口——松手即发，
   这正是原版 LocalSend 的习惯。未选设备时文件会暂存在「待发送」清单

聊天记录、配置与日志存放于 `%APPDATA%\LocalSendChat\`
（可用环境变量 `LSC_HOME` 改位置）。若启动失败，请查看同目录下的 `startup.log`。

## 端口

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 53317 | TCP / UDP | LocalSend v2 收发与组播发现（固定，不可改） |
| 53319 | TCP | 链接分享网页，与协议层完全隔离 |

## 链接分享

点「⤴ 链接分享」→「开启分享」，添加要分享的文件或填写文字，
再点「复制链接」；同一 Wi-Fi 下的手机用浏览器打开该链接，即可下载文件或复制文字。
不需要在手机上安装任何额外应用。

## 双向拖放（v2.6.3 恢复原版拖入即发）

**拖进来（外部 → 聊天窗口）**

- 从资源管理器、桌面拖一个或多个文件/文件夹到本窗口**任意位置**；拖入时
  输入框边框变绿、消息区顶部出现提示条，**松手立即发给当前选中的设备**，
  与官方 LocalSend「拖进去就发送」的行为一致。
- 未选中设备时不会丢文件：文件进入输入框上方的「待发送」清单，状态栏提示
  选设备后点【发送】补发；「＋ 发送文件」按钮也仍然可用。
- 文字片段从浏览器、记事本等窗口拖进来，会追加到输入框；若拖进来的整段
  都是已存在的本地路径，则按文件直接发送。
- 文件夹会自动展开成里面的文件（一次最多 200 个），重复拖入自动去重；
  路径失效或内容无法识别时会给出提示，不会因一次误拖崩溃或卡住界面。
- 「待发送」里每个附件可点 `×` 单独移除，也可一键「清空」。文字与手动
  选择的附件仍在同一后台线程里串行发送，避免对端 409 会话冲突。

**拖出去（聊天窗口 → 外部）**

- 按住**文件气泡**左键拖到资源管理器、桌面或其他接受文件的窗口，松手即在那儿
  **复制一份**；走标准 Windows `CF_HDROP` 复制语义，原文件不动。
- 文字气泡可拖出为纯文本（记事本、Word 等）。
- 源文件已被移动/删除时不注册拖出并提示，不会生成空文件。

**实现**：`app/dnd.py` 负责拖放数据与程序数据的转换，`app/ui.py` 负责界面与发送，
底层用 tkdnd 2.10.3（Windows OLE2），随 exe 附带本地 DLL、运行时不联网。
组件缺失时只关闭拖放，聊天、收发、设备发现等其余功能完全不受影响。

## v2.5.1 修了什么

v2.5.0 把「删除设备」实现成了永久拉黑：删除时往 `chat.db` 的 `hidden_peers` 表写了指纹，
导致刷新与手动添加共用一层过滤后，手机再也回不来；同时顶栏计数读过滤前的原始发现数，
出现「在线 1 台」与「0 个对话」并存的矛盾。v2.5.1 的改动：

1. 删除只删会话行（可选连带消息），**不写任何持久化名单**，下次刷新自然重现
2. 刷新与手动添加共用 `app/visibility.py`；手动输入 IP 通过 `force_visible()` 强制绕过过滤
3. 顶栏与状态栏计数一律基于过滤后的列表，恒等于左侧可见数量
4. 新增独立「屏蔽设备」：右键菜单 + `blocked` 名单 + 左下角「已屏蔽 (N)」逐个/一键恢复 + 设置页入口
5. 「本次新发现 N 台」按设备指纹去重，同一设备占多个 IP 不再被重复计数
6. 补「关于」与双击版本号八次改面板名称

从 v2.5.0 升级后若设备仍不出现：打开左下角「已屏蔽 (N)」点「一键全部恢复」即可。
**不需要**删除 `config.json`（那份文件里只有主题/别名/端口），也不会丢聊天记录。

## 打包形态

发布包为 7-Zip 自解压格式（32 位 SFX），运行时把内置 Python 运行时与程序目录
释放到临时位置；不写注册表、不安装依赖，卸载时直接删除 exe 并清理
`%APPDATA%\LocalSendChat\` 即可。随包分发的第三方组件见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

## 从源码运行

需要 Python 3.11+ 与 Pillow（仓库根目录已提供 `requirements.txt`）：

```bash
pip install -r requirements.txt
python run.py
```

拖放需要 `tkinterdnd2`（Windows 上的 tkdnd OLE2 扩展）。exe 已内置，从源码
运行时执行 `pip install tkinterdnd2`，或把该包放到程序目录旁的 `vendor/`
（本工作区放在 `.workbuddy/vendor/`，不进版本库）。缺这个组件时程序照常启动，
只是拖放自动关闭，输入栏会注明「拖放组件未加载」。

仓库中的 `app/` 即发布包内的程序目录，`run.py` 为启动入口，
`app/assets/` 存放窗口图标与各尺寸 logo。
发布用的 7-Zip 自解压包由本地工具链生成，构建脚本不在本仓库内。

## 已知限制

- 不提供「对方正在输入」与离线消息队列，LocalSend 会话为一次性设计
- 超大文件受局域网带宽限制
- 路由器开启 AP 隔离或组播过滤时可能无法自动发现设备，需用「添加设备」手动填写 IP
- 目前仅提供 Windows 单文件版本
